# 0001 — Note content stored as markdown

Status: **accepted** (2026-10-05, implemented in `f2aa2b8`) · written retroactively 2026-10-14 · the two-copy serializer and the legacy column are **superseded by [0003](./0003-markdown-serializer-fe-only.md)**

## Context

Notes were stored as a Tiptap JSON document (`content JSONB`). The same text was needed in several other forms: display outside the editor, import/export, full-text search and chunking for RAG. Each of them needed its own conversion from JSON, and FTS indexed JSON instead of text.

## Decision

Markdown is the **single source of truth** for note content (`Note.content`, `NoteVersion.content` as `TEXT`). The editor (FE) serializes Tiptap → markdown on save and parses markdown → Tiptap on load.

- Expand/switch migration: `20261005120000_add_content_md` (column `content_md`, filled by the `db:backfill-content-md` script), `20261005120100_switch_content_to_markdown` (refuses to run while any row lacks markdown; the JSON stays as `content_legacy` for rollback; FTS index on `to_tsvector('simple', content)`).
- The conversion rules exist in two copies that must be identical: BE `src/modules/notes/utils/markdown/`, FE `src/shared/lib/editor/markdown/`. Golden fixtures generated by the FE (`UPDATE_GOLDEN=1 npm test`) and copied to the BE (`__fixtures__/markdown/*.{json,md}`) keep them in sync.
- `@tiptap/*` pinned in the BE to `3.20.1` (`overrides`) so the BE serializer matches the FE.

## Alternatives

- **Keep JSON + convert on demand** — every new use (RAG, export) is another conversion and another place to drift.
- **Store both formats** — two sources of truth, a synchronization problem on every save.

## Consequences

- FTS, RAG (`chunkMarkdown`) and export work directly on `content`.
- Editor elements without a markdown equivalent need an explicit representation (e.g. a page reference — fixture `04-page-reference`); every new editor extension needs a rule in both copies and a new fixture.
- The FE uses `^3.x` ranges for `@tiptap/*` — an FE upgrade can change serialization; the golden fixtures catch it, the types do not.
- The local database was reset (no JSON data in any environment), so `content_legacy`, `scripts/backfill-content-md.ts`, `src/modules/notes/migration/` and the backfill step in the `migrator` container are to be removed in a separate migration (done — see 0003).
